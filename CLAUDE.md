# Notenotes

Self-hosted «второй мозг»: заметки, файлы, документы с поиском по всему сразу —
визуально и запросом на естественном языке. 2–10 пользователей (владелец, семья).

Полное ТЗ — [TZ.md](TZ.md). Читай его перед работой над любой фичей: там
зафиксированы решения и осознанно принятые trade-off'ы, а не только требования.

## Структура

```
infra/     Ansible: развёртывание и обслуживание VPS. Работает, сервер поднят.
app/
  backend/     FastAPI (ТЗ §2)
  frontend/    React, веб + Telegram Mini App на одном кодбейзе
TZ.md      техническое задание
```

Команды Ansible выполняются из `infra/`, не из корня.

## Правила, которые нельзя нарушать

Это не стиль, а решения с последствиями. Каждое уже стоило обсуждения —
не переоткрывай их, не спросив.

**PII не попадает в общее хранилище.** Паспорта, финансовые документы и подобное
ждут зашифрованного «сейфа» из ТЗ §16.2 (client-side, пароль не покидает браузер,
Фаза 4). Причина: по ТЗ §16.1 бэкенду нужен плейнтекст для LLM, OCR и векторного
поиска, поэтому в общем хранилище данные принципиально доступны рантайму.
Для PII-документов в индекс и в промпт LLM уходит **только тег/лейбл**
(ТЗ §9), содержимое — никогда.

**Лимит вызовов веб-поиска на один ход диалога — обязателен с первой версии.**
Ориентир 5 (ТЗ §10b, §21.7). Без него агентный цикл сжигает месячный бесплатный
лимит Tavily за один неудачный запрос.

**История версий обязательна, а не опциональна.** Суммаризация диалога
деструктивна и без отката невосстановима (ТЗ §7, §10a, §21.9).

**Авто-теги предлагают, а не молча перекладывают.** Визуально отличаются от
пользовательских, пользователь может удалить (ТЗ §8.2). Доверие к
авто-классификации теряется с первой потерянной заметки (ТЗ §21.5).

**Бэкап перед каждой миграцией БД** (ТЗ §17): `sudo notenotes-backup-now`.

**Формат хранения заметок — всегда Markdown**, независимо от режима
редактирования. Картинки — отдельными файлами, ссылкой; не base64 (ТЗ §7).

**LLM/OCR-провайдер:** не китайские, приоритет европейским (ТЗ §20).

## Ограничения окружения

**4 ГБ RAM — это главное ограничение, а не архитектура.** Сейчас занято
~700 МБ из 3.8 ГБ, но Postgres настроен на `shared_buffers=1GB` и заберёт своё
под нагрузкой. Второй экземпляр Postgres на этот сервер не влезет: если другому
приложению понадобится база, заводи базу и роль в существующем.

**Код исполняется на VPS, редактируется локально.** Локально не нужно ничего
устанавливать — ни Docker, ни Node, ни Postgres: репозиторий это текстовые
файлы. Правим здесь, деплоим на сервер, смотрим результат по домену.

**Отдельного dev-окружения пока нет, и это осознанно.** Приложения нет, база
пуста, пользователей нет — разделять нечего, а второй набор каталогов, базы и
домена был бы сложностью без выгоды. Разделять dev и prod нужно тогда, когда
появятся данные, которые страшно потерять. Тогда: отдельный каталог вне
шифрованного тома, отдельная база в **том же** Postgres (второй экземпляр
в 4 ГБ не влезет) и поддомен.

**Приложение не публикует порты на хост.** Наружу смотрит только Caddy
(порты 80/443). Приложение попадает в интернет через общую docker-сеть `edge`,
и в ней ему нужен **явный alias** вида `notenotes-backend` — сеть общая с
другими приложениями хоста, и два сервиса с именем `backend` столкнулись бы
по DNS.

**Продакшен-сборка фронтенда — точка риска по памяти.** Vite dev-сервер лёгкий
(~300–500 МБ), а вот `vite build` рядом с Postgres может упереться в потолок.
Ограничивай: `NODE_OPTIONS=--max-old-space-size=1024`. Своп в 2 ГБ есть, но он
внутри шифрованного тома и доступен только после unlock.

**Потолок по памяти виден заранее:** Caddy 128 МБ + Postgres 2 ГБ +
Redis 384 МБ + backend 768 МБ + worker 512 МБ ≈ 3.8 ГБ, то есть весь объём
машины. Пока backend'а нет, занято ~700 МБ и запас большой. Когда упрёмся —
расширять VPS, а не ужимать Postgres.

## Секреты

`infra/inventory/group_vars/all/vault.yml` **исключён из git** — репозиторий
публичный, а скачанный зашифрованный файл можно перебирать офлайн без
ограничений по скорости.

Цепочка восстановления, если ноутбук потерян: в менеджере паролей должны лежать
**пароль ansible-vault**, **парольная фраза LUKS** и **пароль restic**. Из них
восстанавливается всё остальное — значения секретов есть и на сервере
(`/srv/encrypted/notenotes/secrets/`), и в бэкапах restic. Без них не
восстанавливается ничего.

## Инфраструктура

Сервер поднят и работает: `https://notenotes.metallcorn.online`.
PostgreSQL 18 + pgvector, Redis, Caddy с автоматическим TLS.

Детали, включая четыре неочевидные ловушки, на которые потрачены отдельные
предохранители, — в [infra/README.md](infra/README.md). Прочитай его перед
любыми изменениями в развёртывании.

Одну вещь надо знать сразу: **данные лежат на LUKS-томе, который после каждой
перезагрузки открывается вручную** (`cd infra && make unlock`). Пока том закрыт,
приложение не запускается — это сделано намеренно, чтобы Postgres не создал
пустой кластер поверх точки монтирования.

## Фазы (ТЗ §19)

   аутентификация логин/пароль, уведомления, история версий, публичный шаринг,

2. Каналы, медиа, AI-слой — Telegram-бот, голос, файлы, OCR, векторный поиск,
   авто-теги, диалоговые заметки с tool-calling. ← сейчас здесь (AI-ассистент,
   авто-теги, OCR, распознавание речи, голос — сделаны; Telegram-бот — нет)
3. Внешние источники — MTProto, Telegram-каналы, RSS
4. Расширения — Google OAuth, Mini App, зашифрованный сейф, MEGA

## Конвенции

- Комментарии и документация — на русском, код и идентификаторы — на английском.
- Схема данных: одна универсальная таблица `items` с JSONB `properties`
  (ТЗ §3). Не заводи отдельные таблицы под типы контента — это осознанный выбор
  ради нулевого трения при добавлении новых типов.
- Миграции БД — только с бэкапом перед применением и тестом на копии (ТЗ §21.6).
